## 1. Demo 中要記錄的 7 類資料

每一類都不能漏。記不齊比記錯更糟。

### 1.1 餐廳基本資料
從對方自我介紹中蒐集，或從 Juliana 詢問中蒐集：
- 餐廳名稱
- 老闆姓氏
- 餐廳所在區（西門町、永康街、信義…）
- 餐廳類型（日料、咖啡廳、早午餐、麵店…）
- 營業多久
- 桌數
- 員工人數（含老闆自己）
- 大概客單價（若提及）
- 營業時段

### 1.2 ICP 過濾三題答案
這是 Juliana 在 demo 前段必問的三題，務必逐字記答案：
1. 一週接待多少組外國觀光客？
2. 目前怎麼處理英文點餐？
3. 現在客人怎麼點餐？

### 1.3 現有系統與工具
- POS 廠牌（iCHEF、Eats365、Dudoo、肚肚、其他、無）
- 結帳方式（現金、刷卡、LINE Pay、街口、其他）
- 發票處理（紙本、電子、無）
- 點餐流程（員工接、紙本、QR Code、混合）
- 外送平台合作（foodpanda、Uber Eats、Lalamove、無）

### 1.4 痛點與需求
不只記「對方說 X 是痛點」，要記「對方原話」。引用越精確越好。
範例：
- 不只寫「員工接單會出錯」
- 要寫「老闆原話：『上禮拜禮拜五晚上排隊排到外面，員工聽錯三筆訂單，被客人罵』」

具體故事 + 時間點 + 後果 = 黃金資料。

### 1.5 Demo 反應（4 段分別記）
demo 4 段分別觀察：
- 第 1 段（客人視角）：老闆什麼表情？有沒有點頭？有沒有皺眉？
- 第 2 段（廚房視角）：老闆對 kitchen display 反應？哪段功能他追問細節？
- 第 3 段（老闆視角）：對後台管理介面反應？對日結報表反應？
- 第 4 段（未來功能）：對 LINE Pay / 綠界發票的時程有沒有追問？

每段反應記 1-2 句即可，但要具體。

### 1.6 老闆提出的問題與 Juliana 的回答
時序記錄：
```
[時間] 問題：「老闆原話」
       回答：Juliana 怎麼回的（重點，不用逐字）
       追問：老闆有沒有追問或滿意？
```

特別注意：
- 老闆問同一個問題 2 次以上 = Juliana 第一次的答案沒打中要害，標記「需重新框定」
- 老闆問 Juliana 答不出來的 = 標記「待補充」，Juliana 必須 follow-up 回覆
- Juliana 承諾「我回去確認再回您」的事 = 全部列出，Demo 後變成 to-do list

### 1.7 Juliana 對老闆的承諾
任何一句「我會 X」「下週 Y」「下次 Z」都要記下來。
這些是 demo 後必須履行的事。漏一個 = 失信。

範例：
- 「我會在這週末前 email 您一份試營運條件」
- 「我下週二再聯絡您」
- 「我會去研究您提到的那個外送平台整合」
- 「我們可以為您客製化菜單翻譯」

## 2. 老闆肢體 / 語氣訊號（人腦觀察，不容易但重要）

| 訊號 | 含意 | 記法 |
|---|---|---|
| 主動拿筆記東西 | 高意願 | 「[時間] 老闆開始記筆記」 |
| 反覆追問價格 | 在認真評估 | 「[時間] 老闆三次問月費結構」 |
| 詢問安裝時程 | 高意願 | 「[時間] 老闆問什麼時候可以裝」 |
| 提到「我跟 X 商量看看」 | 中意願，需 follow-up | 記下 X 是誰（合夥人、配偶、財務） |
| 看手機 / 視線飄走 | 失去興趣 | 「[時間] 老闆看手機 30 秒」 |
| 反覆說「我考慮看看」 | 婉拒中 | 標記為 cold lead |
| 微笑點頭但無具體問題 | 客套 | 標記為 polite-distant |
| 講「我們店比較特別」 | 通常是準備拒絕的鋪陳 | 記下「特別」之處 |
| 主動講競品 | 比較中 | 記下提到的品牌與評語 |

## 7. Max 不要做的 8 件事

1. **不要打斷 Juliana**：即使你覺得她講錯了，等 Demo 結束再說。
2. **不要主動發言**：除非老闆直接問你，或 Juliana 把球丟給你。
3. **不要在鏡頭中吃東西、喝水、看手機**：即使你以為鏡頭沒對你。
4. **不要對老闆的商業決定發表意見**：「您的菜單應該漲價」「您的店應該換地點」這類話絕對不要講。
5. **不要當場修正 Juliana**：如果她口誤或記錯，等 Demo 結束私下講。
6. **不要承諾任何事**：即使老闆問「Max 你覺得呢」，回「這個 Juliana 比較清楚，您直接問她」。
7. **不要讓老闆覺得你只是來湊人數**：偶爾的點頭、微笑、認真聽，傳達你在參與。
8. **不要在 Demo 結束前關鏡頭或下線**：即使你覺得自己不重要，提早離開等於告訴老闆「這場不值得我留」。

## 8. 如果老闆直接問 Max 問題

通用應對原則：
- 如果是產品問題 → 「這個 Juliana 比較清楚」+ 把球丟給她
- 如果是時程 / 行政問題 → 簡短回答（你可以掌握）
- 如果是個人問題（你是誰、做多久了）→ 簡短誠實回答
- 如果是徵求意見 → 「我這邊主要協助 Juliana 整理資料，比較沒立場給意見，不過 Juliana 應該可以分享她的看法」

範例：

**老闆**：「Max 你覺得我的店適合用 Scorder 嗎？」
**你**：「我這邊主要負責整理資料跟筆記，產品適配性 Juliana 比較有判斷依據，您可以直接問她。」

**老闆**：「Max 是工程師嗎？也參與開發嗎？」
**你**：「我主要是協助文件整理跟使用者溝通的紀錄，技術開發是 Juliana 主導。」

**老闆**：「下週幾我可以再跟你們聯絡？」
**你**：「我們週一到週五都可以，我會跟 Juliana 確認後給您具體時間。」

## 9. 緊急情況處理

### 9.1 Juliana 的音訊或視訊斷線
如果你還在線：
- 立刻接話：「[老闆姓氏]，Juliana 這邊好像連線有問題，您先稍等一下，我請她重新連入。」
- LINE 通知 Juliana 重新進入
- 撐 30-60 秒，不要冷場

### 9.2 老闆變得有敵意
不要替 Juliana 應戰。讓 Juliana 處理。你只負責記錄對方原話與情緒升溫的觸發點。
事後分析：什麼話讓對方情緒升溫？

### 9.3 你發現 Juliana 答錯重要事實
不要當場糾正。記下來，Demo 後立刻提醒她寫 correction email：
「[老闆]，今天 demo 中我提到 X，回去確認後正確答案是 Y，特此更正，造成混淆抱歉。」

### 9.4 Demo 結束後老闆要加 Juliana 個人 LINE
這個交給 Juliana 決定。你不要主動分享她的個人聯絡資訊。
LINE OA Premium ID 還沒購買前，建議都走 email。

- 如果對方明確說「這個不要公開」，加註「**[私密]**」標記。

## 11. 範例：完整 Demo 紀錄樣本

```markdown
# Demo 紀錄｜2026-05-10｜小龍麵店

## 基本資料
- 餐廳名稱：小龍麵店
- 老闆姓氏：王
- 所在區：永康街
- 餐廳類型：傳統麵店（牛肉麵、餛飩、滷味）
- 營業多久：12 年
- 桌數：8
- 員工人數：3（含老闆夫婦 + 1 位廚房助手）
- 客單價（估）：NT$200-280
- 營業時段：11:30-14:00 / 17:00-21:00

## ICP 三題
1. 外國觀光客一週幾組：「大概每天 5-10 組吧，週末更多」→ 高
2. 英文點餐處理：「兒子假日來幫忙，平日就比手畫腳，常常點錯」→ 高痛點
3. 現在點餐方式：員工口頭接 + 紙本菜單

## 現有系統
- POS：無（用紙本 + 計算機）
- 結帳方式：現金為主、少數街口
- 發票處理：紙本三聯式
- 外送平台：foodpanda、Uber Eats（外送另記紙本）

## 痛點（對方原話）
1. 「外國客點錯太多次了，要嘛點錯辣度，要嘛多點一碗以為是兩個人份」
2. 「外送單跟內用單混在一起，廚房常常出錯先後順序」
3. 「我兒子說要我換 POS，但我看 iCHEF 介紹覺得太複雜，我老婆學不會」

## Demo 反應
- 第 1 段（客人視角）：點頭多次。在「中英雙語菜單」段表示「這個我需要」。
- 第 2 段（廚房視角）：對訂單分類功能（內用/外帶/外送同畫面）反應強烈，「這個我們現在最亂」。
- 第 3 段（老闆視角）：日結報表「比我現在用筆寫好多了」。
- 第 4 段（未來功能）：問「電子發票什麼時候會有？」（這是他的硬需求）

## 老闆問題與 Juliana 回答（時序）
- [00:09] 問：「員工會不會很難學？」
        答：30 分鐘訓練，Juliana 親自到店。
        追問：滿意。
- [00:14] 問：「你說現在沒有電子發票，那我繼續用現有的紙本可以嗎？」
        答：可以，並行使用。
        追問：「那帳怎麼對？」 → Juliana 答 Scorder 日結 vs 紙本發票需手動對。老闆皺眉。
- [00:19] 問：「我兒子之前看 iCHEF 月費要 NT$3,000 多，你的 NT$1,500 有什麼是他們有但你沒有的？」
        答：列出 iCHEF 完整 POS 範圍，Scorder 只做點餐+廚房+對帳。
        追問：「那我這種小店適合嗎？」 → Juliana 答「適合，您不需要 iCHEF 那些進銷存功能」。

## Juliana 的承諾（必須履行的 to-do）
- [ ] 寄試營運合作說明 email（明天前）
- [ ] 確認外送平台單獨標記功能的細節，回覆王老闆
- [ ] 下週二 5/12 早上 11 點到店看空間

## 肢體 / 語氣訊號
- 全程拿筆記本記重點 → 高意願
- 提到太太學習門檻時皺眉 → 員工接受度是疑慮
- Demo 結束時主動問「下週可以來看嗎」 → Hot lead 訊號

## 老闆下一步意願
[x] 強烈（當場願意進入安裝階段）

## 我的判斷
**Hot**。理由：他主動問下週可以來看店。痛點清楚（外國客點錯 + 外送內用混亂），Scorder 直接打到。電子發票是疑慮但他願意先用現有紙本。

## 備註
- 王老闆的太太是員工接受度的關鍵守門員。下次到店建議讓太太也參與訓練說明。
- 兒子是技術顧問角色。可能影響決策。建議王老闆 share follow-up email 給兒子看。
- 王老闆三次提到 iCHEF，顯然有比較過。Q6 的回答有打中。
```
